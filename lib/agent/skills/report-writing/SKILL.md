# Report Writing（研究报告写作）

## 目标与边界

把实际可用的研究资料写成可阅读、可追溯的 Markdown 报告。优先重组已保存的发现和用户给定素材；对于缺失事实，主动调用可用检索与核验工具，不允许补写未经确认的结果。

**重要**：当前基础包只有 `saveFinding`（写入）而没有 `listFindings`（读取历史发现）。若当前 Agent 上下文里没有已保存发现的内容，不能宣称已从数据库读出全部研究发现；需要由宿主应用注入研究发现，或在第二阶段增加读取工具。

## 写作过程

1. 确认目标读者与报告类型：技术调研、论文综述、研究计划、学术汇报。
2. 确定中心论点，建立“章节 -> 关键结论 -> 来源”的证据映射。
3. 按问题逻辑排列：背景 -> 现有方法 -> 分歧与证据 -> 综合判断 -> 局限与建议。
4. 每一节先写可验证论点，再解释研究依据，而不是堆砌论文标题。
5. 最后核查术语、研究范围、前后口径、DOI/链接、主张的证据强弱。

## 推荐 Markdown 大纲

```markdown
# 研究报告标题

## 摘要
- 研究对象、范围、主要发现、限制

## 1. 背景与研究问题
- 研究动机与问题定义

## 2. 检索范围与资料来源
- 使用的关键词、年份、来源渠道、覆盖范围和局限

## 3. 主要方法与研究现状
### 3.1 方法 A
### 3.2 方法 B
### 3.3 方法对比

## 4. 关键发现与证据分析
- 证据、反例、不同研究结果的适用条件

## 5. 问题、局限及未来方向
- 尚缺哪些验证/实验

## 6. 结论

## 参考文献
- [1] 作者. 标题. 年份. DOI/可点击链接
```

## 引用与事实审核

- 正文使用 `[1]` 等编号；每个编号必须对应参考文献中的真实记录。
- 参考文献至少包含题名、年份、来源链接，作者和 DOI 有数据时补齐。
- 不杜撰页码、DOI、指标、消融结论或论文摘要内容。
- 书目验证 ≠ 结论验证；若只有检索元数据，不能据此直接推断实验结论。
- 若存在互相矛盾的证据，在正文中陈列差异，不强行统一为某个答案。
- 使用 `verifySource` 检查最终保留的重点引用。

## 输出标准

- 默认中文 Markdown，逻辑连续、标题层级不跳跃。
- 重要结论给出来源；推测性判断使用“可能/值得检验”等标识。
- 引用高于文字数量，不能为了充实篇幅编造细节。
- 如果用户需要 `.docx` / PDF 导出，报告文本可以作为输入，但当前代码包**尚未实现文件转换**，不能承诺已经生成该文件。
