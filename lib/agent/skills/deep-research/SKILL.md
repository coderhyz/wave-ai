# Deep Research（深度研究）

## 目标

面对开放性研究问题，不要立刻给出看似完整的答案。先明确研究问题、制定可验证的子问题，迭代搜索与比较证据，最后用可追溯的引用输出报告。适用于技术调研、方案比较、论文综述与研究现状分析。

## 可用工具

- `searchPapers`：通过 OpenAlex 检索论文的题名、作者、DOI、年份、摘要片段和链接。
- `verifySource`：通过 Crossref/OpenAlex 核验文献元数据。`verified` **不表示**研究结论已被证明。
- `saveFinding`：将附带证据、定位符和文献链接的单条研究发现写入当前研究项目的 Neon 数据库；保存前会自动复核文献元数据。

目前尚无通用网页抓取工具、PDF 正文阅读工具、文中语义蕴含验证工具。不得把这三项能力虚构为已经具备。

## 工作流

### 1. 规划研究

- 识别用户的主题、时间范围、对象、地域、比较维度和交付物。
- 明确 3–6 个子问题，例如定义、代表方法、主要结果、反例/局限、未来方向。
- 遇到歧义时作出合理边界假设并说明；严重影响结果的歧义才向用户询问。
- 形成多组检索词，中英文同义词、缩写、邻近概念并用。

### 2. 执行初轮检索

- 调用 `searchPapers` 分别覆盖基础概念、最新进展和代表性方法。
- 不把搜索结果条数或引用量等同于论文质量。
- 去重（优先 DOI，缺少 DOI 时使用 OpenAlex ID）。
- 优先相关性、方法清晰度及来源可信度，而不是简单按被引量排序。

### 3. 证据核验与缺口分析

- 对重点论文使用 `verifySource` 检查身份、DOI、题名。
- 只有在真实来源文本可用时，才可声称某一论文“提出/证明/发现”具体技术结论。
- 只有元数据时，只能确认论文存在、题名、作者、年份、来源；不能推断实验结论。
- 搜索阶段发现相反结论时，分别呈现，并指出研究条件和评价指标的差异。
- 如果信息不足，改写搜索词再次检索；若工具依然不够，应明确“需要阅读论文全文/实证复核”。

### 4. 保存高价值研究发现

当确实取得来源文本或用户提供的可信摘录时，调用 `saveFinding`：

- 一条记录只有一个原子结论（claim），避免混合多项断言。
- `evidenceText` 必须来自明确出处，不能编造引文或页码。
- `evidenceLocator` 填写实际位置，如 `Abstract`、`§3.2`、`p.7, Fig.2`。
- `notes` 记录解释、适用边界、不确定性，不要把推断写成原文事实。
- 如果只有 OpenAlex 的重构摘要，应描述为“索引摘要文本”，不能谎称是 PDF 的逐字摘录。
- `saveFinding` 返回 `claimSupportVerified: false` 是正常的：当前阶段只完成来源元数据验证，未完成论断级别的自动校验。

### 5. 归纳与生成报告

建议输出结构：

1. 研究问题与检索范围。
2. 主要结论（每条引用至少一个可核验来源）。
3. 代表性研究与分歧。
4. 对比表（方法、设定、优势、局限）。
5. 证据限制及仍待核查问题。
6. 参考文献（题名、作者或团队、年份、DOI/来源链接）。

## 研究质量门槛

- 不捏造 DOI、作者、论文标题、研究指标、实验结果和原文引述。
- 无法得到全文/摘要时，不给出论文细节的确定性表述。
- 必须区分“文献检索覆盖不足”和“该方向没有相关研究”。
- 比较结果要解释不同数据集、年份、指标之间不可直接比较的部分。
- 最终答案对每项重要结论给出可点击来源；对于缺失证据的结论标注待核验。
